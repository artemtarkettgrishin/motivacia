# Мотивация — PWA для продавцов сети магазинов стройматериалов

Одна ссылка на телефоне и ПК → магазин → пароль → свой прайс, градации бонусов, категории и акции.
Данные — в **одной Google Таблице** (Apps Script Web App). Хостинг — **GitHub Pages**, сборка без единой env-переменной.

## Стек
- Vite 7 + React 19 + TypeScript, Tailwind CSS 4, lucide-react, xlsx-js-style
- Сборка в один статический `dist/index.html` (`vite-plugin-singlefile`) + `manifest.webmanifest` + `icon.svg` (PWA)
- Local-first: `localStorage` (`mv:local-data:v2`, `mv:local-meta:v2`, `mv:snapshot:v1`, `mv:session:v1`, `mv:pending:v1`, `mv:synclog:v1`)
- Шрифты Manrope (интерфейс) + IBM Plex Mono (цифры)

## Быстрый старт
```bash
npm ci
npm run dev          # локально
npm run build        # dist/
npm run typecheck    # tsc
npm run smoke        # логика прайсов + рендер (jsdom) + синхронизация с мок-GAS
npm run gen:gas      # пересобрать google-apps-script/MotivaciyaBackend.gs из сида
```
Деплой: см. `GITHUB-START.md`. Таблица: см. `google-apps-script/README.md`.

## Конфиг (`src/lib/appConfig.ts`) — один для всех устройств
| Поле | Значение |
|---|---|
| `dataSource` | `'local'` (сид/устройство) · `'google'` (gviz, только чтение) · `'gas'` (Apps Script, чтение+запись) |
| `sheetId` | часть URL таблицы между `/d/` и `/edit` (для `'google'`) |
| `gasUrl` | `…/exec` — если задан, **запись включена в любом режиме** |
| `reportEmail`, `adminPassword`, `companyName` | `otchet@stroimag.ru`, `admin123`, `СтройМаркет` |

Для проверки без пересборки во вкладке «Настройки» можно временно переопределить `gasUrl` только на этом устройстве.

## Как устроена синхронизация (чтобы не было «удалил — появилось» и «тайм-аута блокировки»)
1. Любая правка админа → `saveLocal` + `dirty` → через 1,8 с `syncNow` → `POST saveData` в Apps Script.
2. **Все отправки идут строго по одной** (мьютекс `exclusive` в `sync.ts`): автосохранение, повтор очереди и «Обновить» никогда не накладываются.
3. Успех → `clearDirty + clearPending + журнал ok`. Неудача → `markDirty + savePending + журнал fail` (баннер очереди).
4. **Перед любой загрузкой свежего** (`flushBeforePull`) сначала отправляется очередь; если не ушла — показываются локальные правки, ничего не затирается. Если таблица вернула пустые данные, а раньше были непустые — копия не затирается.
5. Повтор очереди: «таблица занята» → через 6 с, 12 с, 24 с…; сеть/таймаут → 30 с, 60 с… (максимум 5 мин); плюс сразу при событии `online` и при возврате в приложение; кнопка «Отправить».
6. Каждый запрос несёт `saveId`; ответ без совпадающего `saveId` или без `status` (данные вместо подтверждения) считается неудачей и повторяется — запись идемпотентна.
7. Скрипт v7: пишет только **изменённые** листы (сравнение с содержимым), без `autoResizeColumn`, новые значения поверх старых + очистка хвоста (лист никогда не пуст), чтение под блокировкой, при занятости — `code:'busy'` вместо 25-секундного ожидания; пустой payload отклоняется.
8. Старый скрипт детектируется (`gasVersion < 7`, ответ `unknown action`) с понятной инструкцией.

## Модель прайсов (просто)
- **Товар** — одна форма: категория (или «＋ новая»), бренд, название, **магазины** (по умолчанию все; можно выбрать конкретные), и три колонки цен **Базовый / Стандартный / Высокий** (строки «цена от – до → бонус», поле «до» необязательно; хранится как `782-868|22,5` или `869|27,5`), флаги «активен» и «красным».
- **Акции** — те же градации «цена от – до → бонус», сколько угодно ступеней; в печати/Excel каждая ступень отдельной строкой.
- **Плашки магазина** — до 10 на магазин: название, значение, тон (Позитив/Негатив/Нейтрально/Внимание/Цель/Награда одним нажатием), 22 иконки и 10 цветов; плашка и иконка окрашиваются в выбранный цвет. Без выбора — авто: «−» красная, «+» мятная, остальное золотая.
- **Магазин** имеет прайс-группу — она определяет, какую из трёх колонок он видит.
- Продавец видит товар, если он активен, магазин входит в его список (или список пуст) и в колонке его группы есть цены.
- Никаких отдельных «привязок прайсов» и листов `Прайс_*` больше нет.

## Структура таблицы (5 листов)
| Лист | Колонки |
|---|---|
| `Товары` | Категория · Подкатегория · Название · Магазины (через запятую, пусто = все) · Базовый · Стандартный · Высокий (градации `цена|бонус;цена|бонус`) · Красный (`да`) · Статус |
| `Магазины` | Название · Пароль · Прайс-группа · Доп.условия (до 10 плашек `Название|Значение|иконка|цвет` через `;`; иконка/цвет пустые = авто по знаку значения) |
| `Акции` | Начало · Конец · Категория · Товар · Цена · Бонус (первая градация) · Комментарий · Градации (`цена|бонус;цена|бонус`, все ступени акции; пусто = только Цена/Бонус) |
| `Категории` | Название · Иконка · Порядок |
| `Настройки` | Параметр · Значение |

Старая таблица (10 листов) читается автоматически и переносится в новый формат при первом сохранении.

## Печать и Excel (единая модель `src/lib/printLayout.ts`)
A4 **книжная**, поля 1 см, лист = ровно **6 колонок** `[Наименование | цена | бонус] × 2`, ровно на всю ширину (190мм = `CONTENT_W_MM`, сумма ширин не 189/191, а ровно 190). Ширины: «цена»/«бонус» — **по максимальному тексту в своих колонках** (по всему документу — товары, сопутствующие, акции) + отступ, всегда **в одну строку по центру**; «наименование» — остаток ширины половины. Если что-то шире — шрифт целиком для документа **автоматически уменьшается** (стандарт 10pt, до 5.4pt), до тех пор пока всё не вместится без переноса/обрезки. **Высота строки 14.4pt — неизменна**, `wrapText: false`. При переносе на новую страницу шапка `[Наименование|цена|бонус]×2` повторяется (`<thead>` / `!printHeader`). Порядок: основные по категориям → «Сопутствующие товары» всегда ниже отдельной секцией (та же таблица) → «Акции и условия» той же геометрией; комментарии к акциям идут отдельными строками-примечаниями под таблицей мелким шрифтом (не мешают подбору ширины). Вверху — только бейдж «М», магазин и «прайс от {дата}»; внизу — плашки-чипы с иконками. Excel «Прайс» — те же 6 колонок (баннеры секций на всю ширину, тонировка бонуса, мёрджи), книжная `FitToWidth=1`, ширины колонок авто (мм→wch), строки 14.4pt, лист «Акции» — справочник.

## Проблемы и решения
| Проблема | Решение |
|---|---|
| «Прайс пуст» у продавца | Админ → Прайс: у товаров должны быть цены в колонке группы магазина и магазин в списке (или «все») |
| Кнопки шапки неудобны/недоступны на телефоне | На телефоне в шапке кнопок нет: всё в нижнем доке (продавец: Прайс · Акции · **Отправить** · Обновить · Выйти; админ: Прайс · Магазины · Акции · Ещё · Выйти). Статус-бар iOS непрозрачный + запас сверху |
| Как поставить на телефон | Карточка «Как установить приложение?» на экране входа (плюс внизу прайса продавца и в админке: «Ещё», «Синхронизация»): пошагово для iPhone/Samsung/Android/Huawei/ПК; на Android/ПК — кнопка «Установить сейчас» (системный диалог) |
| Правки видны только на одном устройстве | Не задан `gasUrl` (жёлтый баннер в админке) |
| Правки «воскресают» | Скрипт устарел → «Проверить скрипт», вставьте новый код, **Новая версия** развёртывания |
| «Тайм-аут блокировки: другой процесс…» / «таблица занята» | Два сохранения одновременно (телефон + ПК) на старом медленном скрипте. Обновите скрипт до v7 (пишет 1–3 с вместо 10–20); приложение само повторяет через 6–12 с, правки не теряются |
| Скрипт не отвечает | Развёртывание должно быть «Веб-приложение», доступ «Все», URL заканчивается на `/exec` |
| Ввод зумит на iPhone | Все поля 16px + `ViewportLock`; если всё же — обновите страницу (PWA кэш) |
| Письмо не уходит | Без `gasUrl` открывается почтовый клиент (mailto) + скачивается Excel; с `gasUrl` — MailApp |
